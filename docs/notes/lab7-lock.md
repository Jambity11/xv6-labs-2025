# lab7 lock

## Memory allocator

xv6 里，所有 CPU 共用一条空闲页链表、一把 kmem.lock

共用一把锁，实在太慢了，解法是：拆成每个核一个锁，大家各干各的，这时基本不碰到锁

自己的内存不够了，还能去别人那里偷空闲页，这时候会触碰到别人的锁

这种机制叫Per-CPU


## Read-write lock

就是把锁再细分成读写：

- 可以多个读
- 写必须独占
- 有写者排队时，新读者不能插队（写者优先，防止写者饥饿）

**同步原语**

这里没有用信号量，用的是CAS原子操作+自旋

四个操作一句话概括

- 读者拿锁：state 加 1（没写者、没写者排队时才允许）。
- 读者放锁：state 减 1（顺带校验调用顺序）。
- 写者拿锁：先 waiting_writers 加 1，再等 state 变成 0 时- 把最高位置成写者标志。
写者放锁：把写者标志清回 0。
